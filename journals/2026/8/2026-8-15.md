# 📅 2026 年 8 月 15 日 - DSH 动线优化拆解·反馈流程三版选型·鲸鱼视频 9000 小眼睛

## 🚀 核心进展与成果 (Top 5 Actions)

1. **把 DSH 为什么好用给拆明白了——是动线优化不是模型强** 🦿
   * 今天早上从第一性原理一拆，发现它效果好根本不是模型本身强，是动线优化，就像米其林后厨，台面干净、东西放得近，厨师专心炒菜就行。
   * 它的系统提示特别极简，身份就两句、每个工具一句话、运行时上下文也精简，注意力全在任务上；每个工具描述还带反例，告诉你什么时候别用，一个反例比写十句说明书都强，模型就不容易误用；还有那个 narrate 协议，一行⏵汇报进度，跟我在 CLAUDE.md 里一直要求的进度通报是一个思想。
   * **感悟/核心洞察**：这套东西能不能搬到自己家——DSH 的 7 个 skill 打包在第三方 npm 包里，MIT 协议，没有 dsh 特有工具的引用，直接移植了 3 个到我的 Claude Code 环境（vuln-check、audit、release-notes），description 改成中文风格、加触发词和负向约束，顺手把 log skill 也改了。

2. **token 前倾制固化进 CLAUDE.md——收集分析只占 10% 是反的** 🔁
   * 下午跟 AI 复盘工作流，一算发现收集和分析只占 10% 的 token，执行加返工占了 65%，这个比例完全反了。
   * 以后接到任务先把信息收齐、把方向想清楚再动手，想的对做的就对，不然反复返工浪费十倍时间。
   * **感悟/核心洞察**：执行是看得见的进展，但方向错了全白搭；把 token 压到决策上，这才是自动化真正该优化的地方。

3. **反馈流程做三版让我挑，最后选中对话流 B 版** 🚀
   * 反馈流程我先让 AI 做了三版，A 识别流、B 对话流、C 识别仪，同一个功能做三个方向让我挑，最后挑了 B 版对话流开始落地。
   * 每改一轮都上浏览器实测，MutationObserver 精确卡节奏，getComputedStyle 把圆角挨个审计，playwright 开 375px 真机视口，38 个元素字号确认全部偶数，VLM 再截图抽查一眼，改完样式以后实测归零，不靠肉眼猜。
   * 下午详情页又出问题，探索、雷达、反思几个板块反复不显示，改好几轮不对，最后回退到基础版只留照片加 5 层，确认基础渲染正常再一个个加回去，一下就定位到是全局 CSS 的 display:none 把局部样式盖掉了。
   * **感悟/核心洞察**：同一个功能做三个方向让用户挑，比我自己拍脑袋定强多了；复杂渲染里猜不如先回退到最小。

4. **鲸鱼视频被小红书首页推荐，9000 小眼睛** 💬

## 🧠 知识摄取与挑战 (Learning & Challenges)

  * **动线优化**：DSH 好用是因为台面干净、东西放得近、工具带反例，注意力全在任务上。
  * **工具反例比说明书强**：一个"什么时候别用"比十句描述管用，模型不容易误用。
  * **token 前倾制**：收集+分析 10% vs 执行+返工 65% 是反的，要先想清楚再动手。
  * **三版对比选型**：同一功能做三个方向让用户挑，比自己拍脑袋定强。
  * **回退到最小**：复杂渲染排查，先回退基础版确认正常再加回，比瞎猜快。
  * **系统认知**：单用户 vs 场景规则系统，要往上走必须学会建规则。
  * **面临挑战：**
    1. 详情页复杂渲染问题虽定位但后续仍有不确定性。
    2. 哈萨比斯传每天 14 页 + 项目开发，阅读时间紧张。
    3. GOAI 提交在即，反馈流程要赶在 8/16 前落地。
  * **下一步计划：**
    * 反馈流程 B 版继续完善，8/16 前上线。
    * 继续移植 DSH skill 到 Claude Code，工具链加厚。
